# Kost Management Project Agent Guidance

This project uses a reusable CRUD pattern for admin modules.

## Preferred design pattern
- Each data module should use:
  - a searchable table list
  - a single modal form for create/edit operations
  - clear edit/delete actions on each row
  - API-backed load, save, delete operations
- Avoid duplicating CRUD wiring across modules.
- Use `createCrudModule(...)` in `public/app.js` for new entity modules.

## Agent behavior
- When adding a new module, first scaffold:
  1. module nav button in `public/index.html`
  2. module panel with table/list and modal form
  3. new entity config object in `public/app.js` using `createCrudModule`
- Reuse existing helpers for:
  - table rendering
  - form population
  - save payload extraction
  - item filtering
- Keep module-specific code small and declarative.

## Example pattern
- `guestCrud` is the reference implementation:
  - list body: `#guest-list`
  - modal form: `#guest-modal`
  - search input: `#guest-search-input`
  - row renderer and `fillForm`/`getPayload` helpers

## Incremental updates
- New CRUD entities should be added with minimal new DOM event wiring.
- Prefer config-driven logic over copy/paste event listeners.

## Project style
- Use modal-based input for create/edit flows.
- Keep dashboard actions consistent: search, add, edit, delete.
- When a feature needs card or guest assignment, reuse the same pattern.

**DataTables (Default Table Reference)**
- **Purpose**: Use DataTables as the default table renderer via `createGridTable` in `public/app.js` to standardize search, sorting, pagination, and action rendering across modules.
- **Install / Assets**: Install locally: `npm install datatables.net-dt jquery --save`. Serve assets from `/node_modules`:
  - `/node_modules/jquery/dist/jquery.min.js`
  - `/node_modules/datatables.net/js/dataTables.min.js`
  - `/node_modules/datatables.net-dt/css/jquery.dataTables.min.css`
- **Usage**: Call `createGridTable(container, { columns, data, perPage })`. The helper attaches the DataTables instance as `container._dataTableInstance` for programmatic control (search, column filter, redraw).
- **Actions & Delete Flow**: Use the existing `showConfirmModal` for destructive actions; keep action markup using the `actions` class to match global styles.
- **Search / Filter / Pagination**: Built-in DataTables search is used. For per-column filters call `container._dataTableInstance.column(i).search(value).draw()`.
- **Styling**: Wrap tables in a `gridjs-wrapper` element to enable horizontal scrolling; global table styles live in `public/styles.css`.
- **Troubleshooting**: If controls are missing ensure `jquery` is loaded before DataTables and before `public/app.js`. If table overflows, confirm wrapper and CSS rules are present.
- **Reference**: See `DATATABLES_INSTRUCTIONS.md` for full examples and patterns.
